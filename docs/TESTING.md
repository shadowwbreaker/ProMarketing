# TESTING

Статус: стратегия (Phase 0, 2026-11-07). Тестов пока нет — кода нет.

## Правило
Статус `[v] VERIFIED` в roadmap ставится только при наличии прошедшего теста или зафиксированной ручной проверки (команда, результат, дата).

## Уровни
| Уровень | Инструменты | Что покрывает |
|---|---|---|
| Unit | pytest | расчёт среднего, машины состояний, суммы возвратов, парсер ссылок |
| Integration | pytest-django + PostgreSQL в Docker | сервисы с БД, транзакции, блокировки, уникальные индексы |
| API | DRF APIClient | права доступа, формат ошибок, валидация |
| Contract | записанные ответы провайдеров (fixtures) | нормализация ответов TikTok/Instagram/YouTube без сетевых вызовов |
| Payment | MockPaymentProvider | повторный webhook, неверная подпись, частичный возврат, двойной возврат, сбой выплаты |
| Frontend | Vitest + Testing Library | компоненты, формы |
| E2E | Playwright | сценарии A/B/C roadmap 14.3 |

## Обязательные наборы (по мере фаз)
- Phase 1: запуск, подключение БД, миграции вперёд/назад, health, базовый API, frontend ↔ backend.
- Phase 3: лимит обновлений и гонки (два одновременных запроса → одна задача), ошибка не стирает прошлую статистику, отсутствие периодических задач к соцсетям (тест на конфигурацию beat).
- Phase 6–9: все 15 конфликтных сценариев (SUPPORT_AND_DISPUTES.md §5), частичный возврат по сетке.

## Запуск (будет уточнён в Phase 1)
```
docker compose -f infra/docker-compose.yml up -d db redis
cd backend && pytest            # нужен PostgreSQL (DATABASE_URL)
cd frontend && npm test
```
