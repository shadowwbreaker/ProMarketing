# Аудит беты YourVideoTeam от 15 ноября 2026

Проверены сайт и API на Vercel, документация и исходный код ветки `beta`. Запросы на изменение данных, проверки безопасности с тестовыми пользователями и нагрузочный прогон выполнялись локально на отдельной базе PostgreSQL. На Vercel проверялись публичные страницы, доступ без сессии и состояние инфраструктуры.

## Найденные дефекты и исправления

| Дефект | Исправление | Проверка |
|---|---|---|
| Формы входа и регистрации отправляли пароль в URL без JavaScript | Все формы с паролем используют POST | Playwright выполняет HTML-отправку с отключённым JavaScript. Проверяет метод и URL |
| Cookie-сессию можно было создать внешним POST без CSRF | Проверка Django CSRF обязательна до создания сессии, а также при подтверждении email и восстановлении пароля. Фронтенд получает cookie и передаёт токен в заголовке | Запрос без токена и запрос с чужого Origin получают 403. Запрос с валидным токеном проходит |
| Сотрудник без TOTP мог открыть чужой заказ, чат или вложение по прямому адресу. Публичная Django Admin пропускала по паролю | Общая проверка требует TOTP для каждой служебной сессии. Публичная Django Admin отключена | Старая сессия получает 403 даже после включения TOTP в другой сессии. Подтверждённая сессия получает доступ, а публичная Django Admin возвращает 404 |
| Повтор создания заказа с тем же ключом создавал дубликат | Ключ и отпечаток запроса хранятся в PostgreSQL. Фронтенд сохраняет ключ незавершённой отправки в рамках вкладки | Два параллельных запроса возвращают один ID заказа. Тот же ключ с изменённым запросом даёт 409, для другого покупателя действует отдельная область |
| Повреждённый файл с сигнатурой PNG получал статус `CLEAN` | Перекодирование статичных изображений и ограничение числа пикселей. Для PDF, MP4 и анимированных изображений требуется ClamAV. Прежние вложения переведены в карантин до проверки | Проверены неверная сигнатура, повреждённое изображение, удаление посторонних данных из PNG, запрет без сканера и ответы протокола ClamAV |
| Бета подтверждала адрес при регистрации без письма | Публичный режим всегда требует подтверждения фактического доступа к почте. Миграция снимает статус у регистраций без событий подтверждения и сохраняет ранее доказанный статус | Тесты регистрации с неработающей почтой, повторной отправки, подтверждения токена и переноса статусов |

## Защита от флуда

- Vercel DDoS Mitigation работает у обоих проектов. Подготовлены правила уровня Vercel WAF для путей с префиксом `/api/v1/`, фиксированное окно 60 секунд и HTTP 429 при превышении. Для фронтенда порог 240 запросов на IP, для прямого API — 1200. Состояние публикации проверяется отдельно командой `vercel firewall status --project <проект>`. [Vercel WAF Rate Limiting](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting)
- Ограничители API используют общий Redis. В исходном аудите локальный лимит срабатывал после пяти запросов за минуту. Серия из 48 запросов с параллельностью 8 прошла без ошибок. Массовый трафик на публичный сайт не направляли.

## Проверки выпуска

- Бэкенд — 183 теста pytest на отдельном PostgreSQL, включая 10 новых регрессий. Ruff и проверка миграций входят в выпуск.
- Фронтенд — 9 тестов Vitest, TypeScript, ESLint и сборка Next.js. Сценарии Playwright используют актуальные подписи карточки, чата и индикатора непрочитанного.
- Реальную доставку писем проверяют после настройки SMTP. Для Gmail требуется пароль приложения в Vercel, обычный пароль хранить там не нужно.
- В Docker для вложений предусмотрен отдельный ClamAV. На Vercel без доверенного сканера доступны только статичные изображения, а старые файлы сохраняются в карантине. Тесты проверяют протокол и закрытие доступа при ошибке сканера.
- Оплата беты остаётся тестовой. Живые платежи, вход TikTok под реальным аккаунтом, свежие метрики внешних платформ и распределённая атака не входят в этот прогон.

## Порядок выпуска

1. Сохранить архив кода прежней `main` в `old-main` на SHA `00da2d5477a4d891feda71e04d6c90e3f833df3d`.
2. Обновить `beta` и дождаться успешных миграций в Neon. Три миграции добавляют ключ заказа, обновляют старые статусы почты и помещают ранее принятые вложения в карантин без удаления.
3. Развернуть код `beta` на двух проектах Vercel, проверить публичные страницы и API и включить подготовленные правила WAF.
4. Перенести проверенный код в `main`, сохраняя историю обеих веток. `main` в GitHub является основной веткой репозитория. Публичная бета работает в проектах Vercel с `BETA_MODE=true`.
