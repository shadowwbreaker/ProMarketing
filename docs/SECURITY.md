# SECURITY

Текущие правила доступа, почты и вложений обновлены после [аудита от 15 ноября 2026](TEST_REPORT_2026-11-15.md). Разделы с датами сохраняют исторические результаты.

## 1. Аутентификация и сессии
- Пароли: Argon2id (Django `Argon2PasswordHasher`), проверка по списку утёкших паролей.
- Сессии: серверные, cookie `HttpOnly`, `Secure`, `SameSite=Lax`; ротация при входе; выход со всех устройств.
- Подтверждение email, восстановление пароля — одноразовые токены с коротким сроком.
- Для сотрудников и администраторов в публичных окружениях требуется сессия, подтверждённая TOTP. До подтверждения доступны собственный профиль и настройка фактора. Старую сессию можно обновить повторным входом с кодом. Django Admin доступна только в режиме разработки с `DEBUG=True`.
- Публичная регистрация не отмечает email подтверждённым без одноразовой ссылки. Вход и регистрация используют POST даже до загрузки JavaScript.

## 2. Авторизация
- RBAC через разрешения (DECISIONS D-012), проверка только на backend.
- Объектный доступ: каждый запрос к заказу/чату/спору проверяет участие пользователя или разрешение сотрудника. Тесты на доступ к чужим объектам обязательны.
- Финансовые действия — отдельное разрешение + журнал.

## 3. Веб-уязвимости
- SQL Injection — только ORM/параметризованные запросы.
- XSS — экранирование по умолчанию, санитизация пользовательского HTML (не разрешать HTML в чате), CSP.
- CSRF — Django проверяет cookie, заголовок `X-CSRFToken` и Origin на изменяющих запросах с cookie-сессией и на публичных POST входа, регистрации, подтверждения адреса и восстановления пароля.
- Rate limiting — вход, регистрация, сообщения, жалобы, обновление статистики, проверки публикаций.
- Внешние ссылки — валидация домена по платформе, `rel="noopener noreferrer nofollow"`, без серверных запросов на произвольные URL (защита от SSRF).

## 4. Файлы
- Статичные изображения проходят ограничение пикселей, декодирование и перекодирование с удалением метаданных. Для PDF, MP4 и анимированных изображений требуется ClamAV. Там, где ClamAV настроен, он проверяет все загрузки; при ошибке сканера файл не сохраняется.
- SHA-256 считается от выданных байтов. Авторизованный API возвращает вложения только их владельцу, участникам заказа или допущенному сотруднику.
- Ранее принятые вложения переводятся в карантин. `python manage.py rescan_attachments` сверяет размер, SHA-256 и формат, затем отправляет байты доверенному ClamAV. Допущенные вложения сохраняют исходные байты и SHA-256.

## 5. Платежи
- Проверка подписи webhook, проверка источника, идемпотентность, сверка статуса с провайдером, защита от двойных возвратов/выплат (см. PAYMENTS.md §3).
- Mock-провайдер запрещён в production (проверка при старте).

## 6. Секреты
- Только переменные окружения/хранилище секретов. `.env` не коммитится, Claude его не создаёт и не изменяет без разрешения; шаблон — `.env.example`.
- OAuth-токены соцсетей шифруются в БД.

## 7. Персональные данные
- Минимизация, доступ сотрудников по разрешению и с журналом просмотра.
- Удаление по запросу пользователя; для данных YouTube — в течение 30 дней (политика YouTube API).
- Если рынок РФ — требования 152-ФЗ (локализация, согласия) — решение Q-01.

## 8. Аудит и антифрод
- `AuditLog` append-only с хеш-цепочкой.
- Антифрод формирует сигналы для проверки, а не наказания (roadmap Phase 12).

## 11. Изменения 2026-11-08

- **Аватары:** изображение декодируется и перекодируется сервером в JPEG 256×256 (Pillow): метаданные удаляются, файлы-полиглоты не проходят; лимит 5 МБ и 40 Мп (защита от «бомб распаковки»); 20 загрузок в час; выдача с `nosniff`.
- **Сообщения до оплаты:** те же сигналы контактов/реквизитов, что в чате заказа; 30 сообщений в минуту; нельзя писать себе и заблокированным.
- **Подтверждение владения (D-020):** код из `secrets`, только владелец аккаунта, 20 проверок в час, аудит.
- **`DEV_AUTO_VERIFY_EMAIL`:** production отказывается стартовать, если флаг включён.

## Актуализация · 18 ноября 2026

Возврат требует передачи, назначения и arbitration.work даже для старой пустой категории. Участник не рассматривает свой заказ. Владелец требует email-proof. Все API throttle атомарны через Redis; LocMem тестов сериализован. При отказе 503. Порты БД/Redis не публикуются, DB_CONN_MAX_AGE=0. Фикстуры запрещены в production.
